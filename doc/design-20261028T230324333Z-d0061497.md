## 当前架构与具体问题

### JSON-R01：已完成准入，第二遍却不传播构树失败

`src/decode/internal/json_decode_engine.rs` 的 `decode_unique_seed_utf8`（评审时约 574 行）和 `decode_jcs_attempt`（约 980 行）均先调用 `prepare_attempt` 扫描完整文档，然后再次扫描并向 `LexicalJsonValueBuilder` 发送事件。第二遍使用 `scan_with_events`，回调丢弃 `try_accept` 返回值。builder 保留首错，但扫描仍遍历其余输入。

对 `{"x":0,"x":1,"tail":[大量合法数据]}`，第二个 `x` 已决定物化失败，继续第二遍扫描没有业务收益。首遍仍有必要：后续语法错误和预算错误必须优先于较早的重复键。不能把两遍合并成一遍，也不能为提速改变错误优先级。

现有 `JsonLexicalScanner::scan_with_consumer` 与 `JsonLexicalConsumer` 已提供失败即停止的接口；无需增加公共扫描 API。

### JSON-R02：非递归实现仍一次性展开所有兄弟节点

`src/value/internal/json_value_read_ops.rs` 的 `values_equal` 将整层数组元素或对象值压入 `pending`；`debug_value` 为整层节点预先生成全部 action。两个函数被 `SafeJsonValue` 与 `JsonValueRef` 的 trait 实现复用。

现有实现避免 Rust 调用栈递归，但临时堆空间随宽度增长。比较很快不等或输出很快失败的场景仍先承担整层展开成本。改进目标是遍历内部辅助空间 O(depth)，不包括已经存在的输入树、字符串内容及外部输出 sink 的存储。对象比较保留按键查找语义；不能通过配对两个对象的迭代顺序判断相等，因为 `preserve_order` 下插入顺序可能不同。

### JSON-R03：内部协议只能从断言逆推

`src/lexical/internal/json_lexical_cursor.rs` 的 `admission_policy`、`depth_limit`、`defer_number_delimiter`、`max_encoded_string_bytes`、`context` 字段和相应 setter 缺文档。`src/value/internal/lexical_json_value_builder.rs` 的状态字段、`accept_inner`、`accept_decoded_key_inner`、`try_push_value` 缺少事件序列与状态前提说明；读取 helper 也缺文档。

公开 API 的 `missing_docs` 不能证明私有协议说明完整。此项仅补实际合同，不改变错误时机、可见性、属性或运行逻辑。

## 方案选择

| 方案 | 收益及代价 | 决定 |
| --- | --- | --- |
| 复用 fallible consumer；内部惰性遍历帧；定点补文档 | 可复用现有扫描协议，不改变 API 和预算所有权，范围可控制 | 采用 |
| 新建统一解码/遍历框架并迁移所有路径 | 涉及 validated、normalizing、树 visitor 等无关路径，扩大回归面 | 不采用 |
| 仅补文档与基准，保留现有算法 | 风险低，但不能完成 JSON-R01/R02 已确认的改进目标 | 不采用 |

## JSON-R01 设计

### consumer 所有权

在 `lexical_json_value_builder.rs` 为现有 `LexicalJsonValueBuilder` 实现 crate 私有的 `JsonLexicalConsumer<'input>`。`before_value`、`before_key`、`before_number` 返回 `Ok(())`；`event` 直接返回 `self.try_accept(event)`。错误类型为 `JsonValueMaterializationError`。该 trait 实现不改变 builder 的 inherent API，也不引入外部 adapter 或新公开类型。

此 consumer 只负责构树，不替代扫描器的语法、数字模型及预算检查。两个目标路径都必须先完成原有 `prepare_attempt`，再使用关闭重复计量的第二遍 scanner。ordinary 使用 `Integer64`，JCS 使用 `Binary64`，与现状一致。

### 错误与事务

- `Lexical` 仍沿原 `map_lexical_error` 路径映射；JCS 保留自己的外层错误包装。
- `Consumer` 表示 builder 已保存首错。结束扫描后走现有 `finish_guarded` 与原物化错误映射，以保留重复键位置、隐私和错误类别。
- 第二遍不配置 encoded-string 限制，因此 `EncodedStringLimit` 在这两个局部调用中不可达。穷尽匹配时明确这一构造不变量，不把该分支吞成成功，也不添加面向用户的新错误类别。
- 失败时不调用 seed，不提交 value transaction；已消费的输入额度保持原语义。部分树仍由现有 guard 清理，不解包或暴露部分值。
- 该优化不影响 validated 路径的 TokenFirst 或数字策略回调时序。

### 验证重点

保留并扩展 `tests/decode/jcs_decoder_tests.rs::test_jcs_decoder_complete_admission_precedes_materialization_errors`，覆盖重复键后出现语法错误、数字预算失败等情况。为 unique-seed 加同类公开入口回归，并验证失败后 decoder 可复用、输入计费保留、value 用量回滚。

在内部构树 consumer 的测试中使用重复键前缀加非法尾部：首错应为 consumer 重复键，证明扫描不会继续到尾部语法错误。这是对第二遍停止协议的定向测试；公开入口对于同一非法完整文档仍必须由首遍返回语法错误。二者不能混淆。

基准固定重复键前缀，尾部规模取 1 KiB、64 KiB、1 MiB。比较实施前后 unique-seed 与 JCS；首遍始终存在，总复杂度仍 O(input bytes)，仅减少失败后的第二遍工作。不声称整次调用在重复键位置返回或达到固定倍数提速。

## JSON-R02 设计

### 比较帧

新增私有 `JsonValueCompareFrame<'a>`，独立置于 `src/value/internal/json_value_compare_frame.rs`。数组帧持有左右 slice iterator；对象帧持有左侧 map iterator 与右侧 map 引用。`values_equal` 保留当前待比较节点对，加一个祖先帧栈，每次从栈顶取出一个子节点对。

进入容器先检查长度。对象逐键在右侧查找，缺键立即不等；数值、字符串及标量比较沿用原操作符。容器只保存 iterator，不收集全部键值、不克隆节点、不递归调用。可改为自然迭代顺序，比较结果保持一致；当前内部反向遍历顺序不属于公共合同。深度 D 的树最多保留 O(D) 个帧。

### Debug action

新增私有 `JsonValueDebugAction<'a>`，独立置于 `src/value/internal/json_value_debug_action.rs`。保留 `Value`、`Text`、`Key` 角色，增加携带 iterator 和分隔状态的数组/对象 continuation。

处理容器时写开括号，只保存该容器的 continuation；每次 continuation 只安排一个子节点及其必要标点，再保存剩余 iterator。结束时写闭括号。栈上每层只保留常数个 action，保持非递归与 O(D) 辅助空间。输出格式继续为现有 `Null`、`Bool(...)`、`Number(...)`、`String(...)`、`Array [...]`、`Object {...}`，对象沿当前 map 迭代顺序输出。writer 首次返回错误立即传播。

使用普通 `Vec` 保存帧，不改成递归，不引入 unsafe、额外依赖、预算对象或平台专有 API。新增枚举按项目一类型一文件约定放在 `internal/`，不拆分其他领域。

### 正确性和性能证据

公开测试覆盖宽数组/对象的相等、不等、缺键、不同插入顺序、深树和 Debug writer 失败；保留现有所有类型和小栈测试。Debug 小样本使用固定字符串作为预期，不能仅比较 owner 和 view 两个共用同一 helper 的结果。

扩展 `benches/tree_bench.rs` 的计时案例；新增 `benches/value_read_allocations.rs` 作为独立分配诊断 binary，复用已有 `benches/unique_decode_support/allocation_counter.rs` 的计数器，不修改其语义。独立 binary 避免测试线程和其他计时任务混入分配计数；在 Cargo 中注册一个 `harness = false` 的 bench target。

输入树在计量外构造。宽度使用 32、512、8192，覆盖相等、首尾不等及宽对象；分别计量 owner 和 view。Debug 使用不保存输出的计数 sink 和接受固定前缀后失败的 sink，避免 String 输出分配掩盖内部空间。计量操作自身，不计 fixture、打印、结果断言和树析构。另测深度增长，确认空间仍随深度变化。

期望：固定深度增加宽度时，内部比较和 Debug 的请求分配字节不再与宽度线性增长；保持全量正确输出。分配请求总字节、次数不是峰值存活内存，不将二者混称。时间数据只作对照，不以 wall-clock 阈值阻断 CI。若标量/小树出现明显退化，先在同环境重复核实并调整帧表示，不靠降低正确性要求换结果。

1. cursor 五字段及 setter：值的作用、默认值、深度是否包含根、限制单位、检查时机、何时延后数字分隔符以及与 TokenFirst 的关系；说明无界不是无语法校验。

3. `json_value_read_ops` 及两个新增帧枚举：键语义、输出顺序、O(depth) 辅助空间及不包含输入/输出存储的边界、writer 失败传播。
